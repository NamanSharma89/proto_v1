# Healthcare Analytics Platform — Product Spec

## Problem Statement

Hospital operations teams and clinical analysts need fast answers from structured patient
data and unstructured clinical documents. Today, this requires SQL knowledge or manual
report requests. The platform provides a natural-language interface that translates
questions into SQL queries and/or retrieves relevant clinical context, returning
accurate, explainable answers.

## Users

| Persona              | Role                                       | Primary Need                                      |
|----------------------|--------------------------------------------|---------------------------------------------------|
| Clinical Analyst     | Runs cohort queries, quality metrics       | Ask questions in plain English, get SQL results   |
| Operations Manager   | Capacity, admissions, bed utilisation      | Aggregate summaries, trend queries                |
| Data Engineer        | Maintains pipelines, schema, data quality  | Reliable ETL, schema visibility, audit trail      |
| Clinical Researcher  | Protocol adherence, outcome analysis       | RAG over clinical notes + structured data joins   |

---

## Core Capabilities

### 1. Natural Language to SQL (Text-to-SQL)
- User asks a question in plain English
- System classifies intent and routes to SQL pipeline
- Schema retrieved from Redis cache
- Query generated by Meditron-7B (simple) or Claude 3.5 Sonnet (complex)
- SQL validated, executed against RDS PostgreSQL
- On failure: rewrite loop (max 3 retries) before error response
- Result formatted into human-readable answer

### 2. Clinical Document Retrieval (RAG)
- User asks about clinical protocols, treatment guidelines, or notes
- System routes to RAG pipeline
- Bedrock Knowledge Base retrieves relevant chunks from OpenSearch Serverless
- LLM synthesizes answer with citations

### 3. Hybrid Queries
- Questions spanning both structured data and clinical documents
- Step Functions runs SQL and RAG pipelines in parallel
- LLM synthesizer merges both results into a single response

### 4. Intent Routing
- All queries classified by Bedrock Claude before routing
- Intent types: `sql`, `rag`, `hybrid`, `out_of_scope`
- Out-of-scope queries rejected with a clear message

## Non-Functional Requirements

| Requirement       | Target                                       |
|-------------------|----------------------------------------------|
| Latency P50       | < 3 seconds                                  |
| Latency P95       | < 8 seconds                                  |
| SQL Accuracy      | ≥ 82% execution accuracy on benchmark        |
| Hallucination     | ≥ 30% reduction vs. baseline                 |
| LLM-as-Judge      | > 85% approval rate                          |
| Availability      | ECS Fargate, ALB health checks               |
| Security          | No SQL injection, parameterised queries only |
| Auditability      | All queries + results logged to CloudWatch   |
| Cost (dev-cloud)  | ≤ $555/month                                 |

---

## Out of Scope (v1)

- Real-time streaming responses
- Multi-turn conversational memory (beyond single request)
- FHIR / HL7 integration
- Direct EHR system connectors
- PII redaction / de-identification pipeline

## Constraints

- Must run in existing AWS account and VPC (no new account required)
- Terraform is the only IaC tool — no CDK, no SAM
- No vendor lock-in beyond AWS (LLMProvider protocol abstracts model calls)
- OpenSearch Serverless minimum cost ($350/mo) requires business justification before Phase 2
- Meditron fine-tuning dataset must not include real patient PII
